# ADR-0001: 彻底物理移除本地模糊语义缓存

## 状态
已接受 (Accepted) - 2026-09-29

## 上下文 (Context)
在网关初期设计中，引入了内存级的本地语义缓存层（`src/cache/semantic-cache.ts`），旨在拦截重复或高度相似的请求以降低调用成本与响应时延。

但在实际联调与多客户端测试中出现了严重缺陷：**用户不论输入何种问题，网关均返回完全相同的缓存结果**。
经深度溯源排查，根本原因如下：
1. **System Prompt 维度主导坍塌**：现代 AI 客户端（如 OpenCode、Chatbox、Cursor 等）在发起请求时，通常会携带长达 300~1000 字符的全局系统提示词（System Prompt）。在对整个 Prompt 进行向量嵌入或 N-Gram 词袋提取时，静态的系统提示词占据了 90% 以上的权重，导致用户实际提问（仅几十字符）即使完全风马牛不相及（例如“25*4等于多少”与“中国首都是哪里”），计算得到的余弦相似度依然高达 `0.9903`，严重突破预设的 `0.95` 相似度阈值。
2. **弱嵌入模型语义反转失察**：轻量级字符级相似度无法区分关键语义否定词（如“不要删除”与“立即删除”）、细微数字差异（`25*4` vs `25*5`）以及代码细微修改。
3. **架构污染与残留风险**：若仅采用配置项软开关（`enabled: false`），未来极易因为配置疏漏或下游隐式依赖而再次引入难以排查的“串味”Bug。

## 决策 (Decision)
1. **物理删除而非配置关闭**：
   - 彻底删除 `src/cache/` 整个目录（包括 `semantic-cache.ts` 与 `prompt-cache.ts`）。
   - 从 Orchestrator、Server、FinOpsTracker 及核心数据类型中物理移除全部本地缓存相关代码，确保代码库干净、零残留。
2. **转向纯正的上游 Prompt Caching**：
   - 保留规范化提示词前缀的能力（PromptOptimizer），使请求天然最大化命中上游官方 Provider（如 Claude、OpenAI、DeepSeek）的 KV Cache。
   - 仅在计量层面（FinOps）如实统计上游返回的 `cached_tokens`，网关自身坚决不做任何黑盒的本地结果伪造或语义拦截。

## 后果与影响 (Consequences)
- **正面影响**：
  - 100% 杜绝了不同请求之间的交叉污染与“串味”问题，每次请求均独立穿透真实上游。
  - 简化了网关内部管道复杂度与内存开销，大幅降低了排查与维护成本。
  - 保持代码干净透明，符合极简可靠的微服务设计原则。
- **负面影响 / 代价**：
  - 完全相同的重复提问将不再有“0ms 本地命中”效果，每一次重复请求都必须向上游计费调用（但可通过上游 KV Cache 获得折扣）。
